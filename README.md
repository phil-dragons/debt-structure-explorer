# Debt Structure Explorer

한국어 중심의 반응형 채무 구조 학습 사이트. HTML/CSS/JavaScript만 사용하며 설치·빌드·외부 라이브러리·API 키가 필요 없습니다.

## 실행

이 폴더의 `index.html`을 브라우저로 열면 사용할 수 있습니다. 자동 저장 및 파일 내려받기 동작은 브라우저의 로컬 파일 정책에 따라 제한될 수 있으므로 로컬 서버 사용을 권장합니다.

터미널에서 이 폴더로 이동한 뒤:

```sh
python3 -m http.server 8765 --bind 127.0.0.1
```

브라우저에서 `http://127.0.0.1:8765`를 엽니다. 서버 종료는 Ctrl+C입니다.

## 기능

- **Explore**: 원래 25개 기준을 5개 그룹으로 분류, 한영 검색, 기본/상세 설명, 12개 용어 항목.
- **Compare**: 8개 대표 예시 중 2~4개 비교, 25개 속성과 회계 계정 후보, 차이점 필터, SVG 관계도.
- **Build**: 25개 속성 선택, 8개 시작 예시, 실시간 조건 충돌·추가 검토 안내, 회계 계정 후보, SVG 관계도.
- 기기 내 자동 저장, 초기화, JSON 내보내기. JSON 다시 불러오기는 제공하지 않습니다.
- 모바일 단일 열, 비교표 내부 가로 스크롤, 키보드 초점 표시, 입력 레이블, 실시간 안내.

## GitHub Pages에 게시

**현재 외부 게시하지 않았습니다.** 아래 단계는 공개할 GitHub 계정·저장소를 정하고 사용자 확인을 받은 다음 실행합니다.

1. GitHub에 로그인하고 게시용 저장소를 준비합니다. 공개 저장소를 사용한다면 소스도 공개됩니다.
2. 이 폴더 **안의 파일**을 저장소 최상위에 올립니다. `index.html`이 최상위에 있어야 합니다. 테스트 파일과 README는 실행에 필수는 아닙니다.
3. 저장소의 **Settings → Pages → Build and deployment**에서 **Deploy from a branch**를 선택합니다.
4. 파일을 올린 브랜치(예: `main`)와 **/(root)**를 선택하고 저장합니다.
5. 배포가 완료되면 Pages 설정에 표시된 URL을 열어 세 화면을 확인합니다. 일반 프로젝트 주소는 `https://사용자명.github.io/저장소명/` 형태입니다.

`.nojekyll`을 포함했습니다. 상대 경로를 사용하므로 프로젝트 하위 경로에서도 동작합니다. 별도의 GitHub Actions 설정은 필요하지 않습니다. Pages 이용 가능 범위는 계정·저장소 설정에 따라 달라집니다.

공식 안내: [게시 소스 설정](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site), [Pages 사이트 만들기](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site).

## 개념 설계

원래 목록의 번호와 범주를 유지하되 4번은 인원수와 책임 방식을 함께 설명하고, 12번은 증권 발행과 자산유동화를 구분하도록 명칭·선택지를 다듬었습니다. 15번의 금액은 주된 지급 원금 기준입니다. 여러 기준은 완전히 독립적이지 않습니다.

- 대출은 거래 원인, 차용증·어음은 문서/권리 형태입니다. 대출과 약속어음이 함께 존재할 수 있습니다.
- 일반적인 받을 권리(claim)와 채권증권(bond)을 구분합니다.
- 양도 가능, 실제 유통시장, 증권 발행, 자산유동화는 별도 개념입니다.
- 환어음의 지급 지시는 송금 대행과 다릅니다. 도식은 인수 후를 가정하며 발행인·배서인의 소구책임 전체를 표현하지 않습니다.
- 자산유동화 선택 시 도식은 기초관계만 나타냅니다. 기초자산·발행주체·이전/신탁 구조를 모델링하는 완전한 유동화 설계 도구가 아닙니다.
- 계정명은 채무자 관점의 후보입니다. 기초채무와 어음의 이중계상 여부, 유동/비유동 분류, 전환권 분리 등의 회계 처리는 판단하지 않습니다.
- 조건 충돌은 모형의 가정 또는 어음의 기본 요건에 대한 안내입니다. 경고가 없다는 사실은 적법성·적합성 보증이 아닙니다.

근거 링크는 사이트 하단에 포함했습니다. 어음법 제1·28·33·75·77조, 민법 제449·450조와 Investor.gov의 채권·유동화 설명을 참고하는 교육용 구성입니다. 실제 거래에는 최신 법령과 개별 계약 검토가 필요합니다.

## 확인 결과 · 2026-10-11

- JavaScript 문법 검사 통과.
- 25개 기준, 8개 예시의 전 항목 값과 기본 예시 내 충돌 없음 확인.
- 조건부 어음, 변동금액, 구두 증서, 분할 만기, 지급구조, 없는 담보/보증 청구, 발행인 유형, 자산유동화 추가검토 시나리오 검사.
- 로컬 서버 HTTP 200 및 실제 브라우저 실행 확인.
- 검색(담보: 4개 기준), Compare 기본 25행 + 계정 행, 차이점 필터(14개 차이 + 계정 행), Build 조건부 약속어음의 충돌 안내 확인.
- 환어음 예시 선택과 새로고침 후 자동 저장 복원 확인. 초기화 후 충돌 0개 확인.
- 넓은 화면 및 모바일 화면 시각 확인. 브라우저 실측 CSS 너비 1163px와 354px에서 문서 가로 넘침 없음.
- 브라우저 콘솔 오류 없음.
- JSON 내보내기 버튼은 구현했으나 브라우저 자동화의 내려받기 완료 감지가 시간 초과되어 실제 다운로드 파일은 검증하지 못했습니다.
- GitHub Pages 실제 배포 및 다른 브라우저·실물 모바일 기기 테스트는 수행하지 않았습니다.

## 개인정보

서버로 입력을 전송하지 않습니다. Build 선택만 브라우저 localStorage의 `debt-explorer-v1`에 저장하며 저장이 차단된 환경은 안내 문구를 표시합니다. 초기화는 차용증 예시로 값을 덮어씁니다. 외부 출처 링크를 누르면 해당 공식 사이트로 이동합니다.
